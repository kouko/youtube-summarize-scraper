## Problem
目前 ytss 只支援 CLI 模式（`go run . run -c <config>`），使用者無法在終端機中：
1. 直觀選擇設定檔（需記得路徑或打完整路徑）
2. 一眼看懂設定檔內容（需自行 cat 檔案或記住參數）
3. 即時掌握執行狀態（只能看日誌滾動，無法快速掌握進度、錯誤、目前處理的影片）
4. 快速切換設定檔重跑（需重新輸入指令）

目前的「watch 模式」只能在背景跑，看狀態只能開另一個終端機 tail log，體驗不連貫。

## Proposed outcome
- 新增一個 TUI（終端機互動介面，基於 bubbletea），啟動後直接進入全螢幕介面
- 四大區塊：
  1. 設定檔選擇：檔案系統瀏覽器（filepicker），顯示所有目錄/檔案，只允許選 .yaml/.yml
  2. 設定內容：解析後的結構化表格（Key-Value 表格），可切換回原始 YAML
  3. 執行狀態：即時顯示 Watch iteration、處理佇列、已處理/跳過/失敗/部分、目前影片與階段
  4. 最近事件：即時日誌流（最後 N 筆，ERROR 紅色高亮）
- 鍵盤操作：上下選檔、Tab 切區塊、c 切換結構化/原始、p 暫停/繼續、q 退出
- 背景透過事件橋接層（slog tee handler + bounded channel）非阻塞接收日誌，更新共享 AppState，TUI 每 250ms 讀取快照重繪

## Acceptance
1. 啟動 `go run . tui` 直接進入全螢幕 TUI，不帶參數預設掃描常用目錄
2. 檔案瀏覽器（filepicker）顯示所有目錄/檔案，只允許選 .yaml/.yml（Enter 選檔，Enter 進目錄，Backspace 返上層）
3. 選中設定檔後，右下自動顯示結構化表格（Key-Value 表格，巢狀 key 用點號扁平化），按 c 可切換原始 YAML
4. 執行狀態區即時顯示：Watch iteration、佇列長度、Processed/Skipped/Failed/Partial 計數、目前影片與階段
4. 最近事件區即時滾動顯示最後 10 筆日誌，ERROR 紅色高亮
5. 鍵盤操作：↑↓ 選檔、Tab 切換焦點、c 切換結構化/原始、p 暫停/繼續（若支援）、q 退出
6. 按 Enter 選中設定檔後，底部提示「按 r 開始運行」，再按 r 啟動 pipeline（背景執行，TUI 繼續顯示狀態）
7. 按 q 退出時，若 pipeline 正在跑，提示確認是否終止

## Constraints
- 不改動現有 Pipeline 核心邏輯，只在 main.go/root.go 加入事件橋接與 TUI 啟動
- 事件橋接層不得阻塞 pipeline（有緩衝 channel、非阻塞寫入）
- TUI 渲染間隔 ≤ 300ms，不得造成明顯延遲
- 保留原始 CLI 行為：`go run . run -c <config>` 仍正常運作

## Value case
- 受益者：需要在終端機直接觀察 ytss 執行狀態、快速切換設定檔、除錯設定的使用者
- 急迫性：目前除錯需開多個終端機、tail log，體驗斷裂
- 現有替代方案：多開終端機 tail -f log、或加 -v 參數看更多日誌
- 被排擠的工作：無明顯排擠，新增功能不影響既有 CLI

## Out of scope
- 設定檔編輯器（TUI 內編輯 YAML）
- 多視窗分割（目前四區塊固定版面即可）
- 遠端監控/HTTP API（本地終端機即可）
