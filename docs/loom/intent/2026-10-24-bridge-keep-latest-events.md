# 事件橋在爆量日誌下保留最新事件
originator: kouko
kind: product
needs-design: yes — TUI Recent Events 面板在日誌爆量下的可見內容改變（保留最新而非最早），倉庫沒有 DESIGN.md 或 ui-flows 文件涵蓋該面板的溢出行為
status: confirmed 2026-10-24

## Problem
TUI 的 Recent Events 面板在日誌爆量（超過面板上限）時，顯示的是最早的一批事件而不是最新的。使用者在長時間批次執行中看到的是過時的開頭日誌，最新的進度資訊反而被丟棄；正在跑的 pipeline 後半段的訊息完全看不到。

## Proposed outcome
事件橋的佇列在滿時淘汰最舊的一行、保留最新的一行，讓面板在爆量下始終顯示最新的活動；丟棄與應用的計數仍然準確，寫入端永不阻塞。

## Acceptance
1. 爆量寫入（超過佇列與面板上限）後，面板保留「最新」的上限行數，內容為寫入序列的連續後綴且順序不變；既有的爆量 probe（2026-10-13 變更的證據檔）由失敗轉為通過。
2. 佇列滿時的寫入不阻塞，丟棄與應用計數之和等於寫入總數（每一行恰被應用或丟棄一次）。
3. 既有橋行為不回歸：單行/多行/片段寫入、消費者停止時的丟棄計數、應用後通知回呼、容量與面板上限一致——既有橋測試全部通過。
4. CI 的 test job（`go test -race ./...`）通過，PR #72 的檢查轉綠。

## Constraints
- 修復範圍限 TUI 事件橋的佇列機制；不改 pipeline 寫入端、不改面板渲染。
- 保持既有語意：部分行緩衝（片段等待換行）、應用後通知回呼、Close 冪等並等待消費者結束。
- 與 PR #72（s 停止鍵）互不影響；修復先行進主線，#72 的 CI 重跑即綠。

## Value case
- 受益者：長時間批次執行中看 TUI 的使用者；以及所有後續變更（CI 不再被既有 probe 阻擋）。
- 急迫性：高——它擋住 PR #72 的合併。
- 既有替代方案：調整 probe 斷言迎合現狀（使用者已拒絕）；接受 CI 長期失敗（已拒絕）。
- 排擠的工作：無。
- GO。

## Out of scope
- 佇列實作以外的橋行為（片段緩衝、通知、Close）。
- pipeline 端的日誌量控制。
- 其他面板。
