## Problem
在 TUI 裡看得到執行紀錄與紅色錯誤訊息，但無法用滑鼠選取複製：程式接管了整個終端機畫面與滑鼠事件，拖曳只會操作面板，不會選字。想回報錯誤或自己查原因時，只能靠記憶、截圖或手打；程式關掉後紀錄也不存在，重開就看不到上一次的錯誤。

## Proposed outcome
每次執行時，程式把自己產生的執行訊息寫成一份純文字日誌檔，放在輸出資料夾裡。使用者可以用任何編輯器開啟、選取、複製日誌內容，也能在程式結束後回頭查閱之前執行的紀錄。

## Acceptance
1. 執行一次批次（或單支影片）後，輸出資料夾的 logs 子目錄內出現日誌檔，內容包含該次執行的處理訊息（例如影片處理的各階段）。
2. 日誌檔是純文字，用一般編輯器開啟後可以正常選取並複製內容。
3. 連續執行兩次，日誌檔保留兩次的紀錄；第二次執行不會清除或覆寫第一次的內容。
4. 日誌檔內容只來自程式自己的日誌；外部抓取與轉錄工具的原始進度輸出不會出現在檔案中。
5. 日誌檔中不出現 cookie、keychain 內容或 API key 值（掃描檔案內常見機密格式即可判別）。
6. TUI 畫面（事件面板、按鍵）的行為不變。

## Constraints
- 日誌檔預設放在輸出資料夾內（使用者指定「跟著輸出資料夾」），位置在 logs 子目錄。
- 只記錄程式自己的日誌；外部工具的原始輸出維持丟棄，不進日誌檔。
- 附加模式寫入、低 I/O，不逐行強制落盤。
- 不得洩漏 cookie、keychain 內容或 API key（PRINCIPLES 非協商項 2）。
- 既有 TUI 畫面與按鍵行為不變。

## Value case
beneficiary: 在 TUI 跑批次、需要把錯誤訊息帶出程式或事後查閱執行紀錄的使用者（即使用者本人）。
urgency: 中——目前錯誤訊息只能看不能帶走，回報與除錯都被卡住。
existing alternative: Ghostty 按住 Shift 拖曳選取（Herdr 多一層攔截時不一定有效）、截圖、手動重打。
displaced work: 無，不取代任何現有功能。
GO — 成本低、直接解除「錯誤訊息無法帶出程式」的痛點，且不改變既有畫面行為。

## Out of scope
- 自訂日誌路徑的設定選項（本次固定預設位置，日後需要再加）。
- 日誌輪替或大小上限。
- 在 TUI 內加複製快捷鍵。
- 改變日誌內容的種類或格式（維持現有訊息）。
