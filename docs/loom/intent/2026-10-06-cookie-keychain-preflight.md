## Problem
需要登入才看得到的 YouTube 清單（例如「稍後觀看」），在電腦重開機後可能好幾週都抓不到新影片，而使用者完全不知道。
程式只說「清單不存在」，看不出真正原因是瀏覽器的登入資料讀不到；使用者得自己翻查、手動測試才找得出原因。
這次從 9/23 重開機後就沒再抓到「稍後觀看」，直到 10/6 才發現。

## Proposed outcome
- 設定了「從瀏覽器讀取登入資料」時，程式一啟動就先確認讀得到；讀不到就直接停止，並告訴使用者原因和怎麼修復。
- 執行過程中如果抓取失敗的真正原因是登入資料讀不到，錯誤訊息要直接說明這件事，而不是只轉述「清單不存在」。

## Acceptance
1. 在 macOS 上、設定使用 Chrome 登入資料、登入資料無法讀取（鑰匙圈鎖住）時執行程式：程式在處理任何頻道或清單之前就停止，結束代碼不是 0，訊息說明登入資料讀不到，並附上可直接執行的修復指令。
2. 同樣的設定、登入資料可以讀取時執行程式：行為與現在相同，沒有多出的停止或警告。
3. 沒有設定任何瀏覽器登入資料（不用 cookie，或改用 cookie 檔案）時執行程式：行為與現在相同。
4. 執行過程中抓取失敗、而失敗原因是登入資料解密失敗時：錯誤訊息明確指出是登入資料讀不到，而不是只顯示「清單不存在」。

## Constraints
- 檢查失敗時直接停止，不是警告後繼續（使用者在 2026-10-06 選定）。
- 不得把鑰匙圈的內容（解密金鑰）印出或寫進 log。

## Value case
- 受益者：用瀏覽器登入資料抓「稍後觀看」等私人清單的人，特別是無人值守執行的情況。
- 急迫性：問題會無聲持續好幾週；這次已經漏掉 9/23 到 10/6 的「稍後觀看」。
- 現有替代方案：每次重開機後記得手動解鎖，或自己定期檢查輸出資料夾，兩者都靠人記得。
- 被排擠的工作：無明顯排擠，改動範圍小。
- GO — 失敗是無聲的，而且已經實際造成約兩週的資料遺漏。

## Out of scope
- 程式自動幫使用者解鎖鑰匙圈，或儲存使用者的系統密碼。
- macOS 以外的作業系統，以及 Chrome 系以外的瀏覽器的啟動檢查。
- 推播、Email 等額外的通知方式。
