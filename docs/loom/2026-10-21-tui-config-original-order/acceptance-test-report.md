## 對你既有的資料做了什麼 (what this did to data you already had)

你的兩份設定檔——倉庫目錄下的那一份，以及 vault 裡的 ytss-config.yaml——各被刪掉一行最上層的 `random_order: true`（那個隨機顯示開關已經失效，刪掉後畫面才不會多出一列沒有意義的資料）。其餘內容、順序與註解都沒有動，批次處理的 `random_order` 也原樣保留。這次沒有另存備份檔；被刪掉的只是一行已失效的開關，那行長什麼樣子記在證據檔裡。舊形式的設定仍然可以正常讀取：如果某個設定檔還帶著最上層的 `random_order`，它會被當成一列普通資料顯示與保存，不會被丟棄。另外提醒一點（不是這次改動造成的）：從設定畫面存檔時，檔案的縮排會被正規化成 4 格空白，順序與註解不變——這在改動前就是如此。

## I decided for you

- **把整個隨機顯示功能刪掉，而不是留一個預設關閉的開關** — 因為你的要求是設定畫面照檔案順序顯示、隨機顯示對你沒有意義，留著只會是死程式碼。之後若要恢復這個功能，需要重新寫一遍。
- **顯示用的資料就是載入的設定檔本身，不再為了顯示去改它** — 這是修好「存檔弄亂檔案」的方式：之前為了隨機排列會先改動這份資料，存檔時就把改動寫回檔案。之後若想在顯示時做任何轉換，必須改用「只改顯示用的副本」的做法。
- **對抗測試提出的兩點小問題（皆為既有行為、與本次變更無關，故未處理）** — 其一：從設定畫面存檔時，yaml 序列化會把縮排從 2 格重新排版成 4 格（順序與註解不變），改動前後行為相同；若你要求存檔後位元組完全不動，需要另外換序列化方式。其二：文件裡關於執行 Go 測試指令寫法的一行小提醒，屬既有文件的文字。
- **其餘都是你決定的或別無選擇** — 刪除你兩份設定檔裡的最上層 `random_order` 一行，是你先前明確確認過的；不動 `batch.random_order` 是這次明確列在範圍外的。
